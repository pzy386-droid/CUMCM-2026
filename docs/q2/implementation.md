# 实现、实验与Git

## 分工与模块

保留Q1已完成版本；复用经过验证的物理和账本逻辑，移除Q2不应继承的每日终值约束。
fable负责src/microgrid、生产测试、Q2输出及实现报告。审查方维护本目录规格及review/tests/review；发现矛盾交回，不改验收器让错误通过。

建议新增inputs_q2、forecast_q2、scenarios_q2、policy_q2、model_q2、execute_q2、simulate_q2、export_q2、q2模块，可按现有结构调整。
分离：历史可见性、预测、情景、优化、物理执行、费用、输出。

实现入口：
`python -m microgrid.q2 --config configs/q2.json --output outputs/q2/<run_id>`。
config和CLI实际契约由实现补齐并说明。Python src布局先安装项目或设置PYTHONPATH；pytest的pythonpath不能代替普通CLI安装步骤。

## 实现顺序

1. 先读完本交接与原始材料，落实配置、接口和数据截止时刻。
2. 物理投影、单独费用函数、跨日账本和手算测试。
3. 因果预测与确定性点预测调度基线；冷启动从1月1日运行。
4. 联合残差档案、8情景、2维共享规则及虚拟尾部。
5. 0/6/12/18更新，合同冻结与未来扰动测试。
6. 连续20日性能预检，记录求解耗时/gap/可行性/投影/回退。
7. 全年365日顺序回放，生成334日提交区间、四指定日论文表、Excel读回。
8. 比较真实费用，提交完整可复现交付。

20日预检后若规模过大，优先减少情景、改进稀疏组装/重复计算。不要先跑全部超参数组合，不得通过删除因果约束换速度。

## 点预测基线定义

使用相同历史预测和终端价值，以预测路径做确定性调度，得到0时合同和储能动作计划。
日内按相同0/6/12/18频率更新剩余储能计划，合同固定；当前段将计划内部储电增量送入相同物理投影。
真实费用只来自同一实际数据回放。基线也不能使用未来实际值。
主方案对比基线时保持设备、价格、执行时刻、计费和评估日期一致。

## 求解状态和失败

Q1严格数值最优验收不机械套到Q2全年滚动规模：
- 分开求解器停止gap与交付报告状态。
- 设置可配置的时间上限和目标gap，先按20日预检定合理值；记录每次状态、界、实际gap、节点、时间。
- 时间到但有可行解：复核完整约束、共享规则、有限性后才可用，标记feasible/time_limit，不写optimal。
- 无合法可行解：执行预先规定的因果回退，不删日期。
- 日内回退保留原合同及上一合法策略快照；策略需携带其预测/特征版本，不能换了基准继续套旧系数。
- 0时回退g=max(预测净负荷,0)，x_raw=0，再由投影及应急保障。
- 1月1日按专门冷启动g=0、x=0。
- 失败不能借助未来实际曲线生成补救最优解。

检查S/参数/目标/模式有限性，模式整数性，完整线性约束和变量界。默认可参照能量/SOC容差1e-6kWh，费用容差max(1e-5元,1e-8×费用尺度)，具体统一配置并披露。

## 输出原子性与追溯

每次实验独立run_id目录，禁止直接中途覆盖正式旧输出。
先生成临时完整输出并读回，再发布该次完成状态。
状态标记区分running/failed/completed，保留上次成功结果但不冒充当前尝试。
元数据绑定代码SHA、配置文件内容哈希、源数据哈希、种子、信息截止时间、策略快照ID。
若存在未提交源代码，记录source_dirty=true，不伪装干净。

## 必做实验

- 点预测基线 vs 共享规则主方案。
- 主方案仅0时规则 vs 0/6/12/18更新（两者合同均固定）。
- 未来扰动、合同冻结、跨日衔接。
- 至少一个小规模终端价值敏感性，报告期末SOC。
- 全年现金费用分项、应急量/正段数/事件数、富余量、最差日费用、期初期末SOC、求解/回退/投影统计。
- 各策略自行一月启动的主回放之外，另做统一2月初SOC的受控比较。

资源允许才做8/16/24情景、31/60日窗口、L1预算1/2/4、预测偏差校正。若用于选参，只能历史验证；若用全部评估期展示敏感性，明确是事后分析，不冒称样本外选参。

不要求提前获得“主方案必胜”结论。费用更高时分析预测、情景、规则限制、投影及终端影响，保留不利结果。
不做DRO、Transformer、强化学习或遗传算法替代可求解的规划。
两阶段全路径自由追补若作为对照，其情景内目标不能当真实成绩或未经证明的下界。

## Git交付

从q2-spec-v1建立实现分支；公共代码变化跑Q1回归。
分阶段提交：数据/账本/执行器 → 基线 → 主模型/滚动 → 测试/性能 → 结果。
代码先提交，再生成正式结果，结果记录该代码SHA。普通push到codex/q2-implementation，不直接推main。
push失败则交付真实错误和包含完整提交链的bundle，禁止声称已上传。
共享回滚使用revert；避免覆盖其他人的修改。
