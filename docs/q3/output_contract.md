# result3.xlsx 与证据文件契约

## 1. 原模板与明确修正

保留 `data/templates/result3.xlsx` 原件。输出仍叫 `result3.xlsx`，工作表顺序严格为：计划购电量、调整购电量、充放电量、紧急购电量，不增加内部账本表。

原模板首段为 `0:10-0:20`，末段越到次日 `0:00-0:10+1`，遗漏当天第一段。继承 Q1/Q2 已采用的修正：输出副本两张购电表的 B:EO 共144列改为 `00:00-00:10` ... `23:50-24:00`；记录 `template_mapping.csv`，原标签、修正标签、列号、输入标签、slot 一一对应。不能声称原模板文字毫无修改，也不能默默错移一段。

## 2. 四张表的数值

| 表 | 结构 | 具体含义 |
|---|---|---|
| 计划购电量 | 335 行×147 列 | A为334天日期；B:EO为每天0时提交的g；EP=Σg；EQ=Σp*g（仅原计划费） |
| 调整购电量 | 335 行×147 列 | B:EO为每段交付时最终有效a，非增减量；EP=Σa；EQ=完整当日J3（计划+调整+紧急） |
| 充放电量 | 2005 行×6 列 | 每天6个四小时段，逐段累计c,d；每日日初和日末S按Q2样式填写 |
| 紧急购电量 | 3列、行数动态 | 日期、连续正e的区间、区间累计e；无应急日显式日期+0占位，无虚构事件 |

购电表两个“全天购电费”的含义不同，是原融合方案选定的填表解释。必须随交付说明，不能将两列再次相加。主结算 a>=g 不意味着每次修订的 a 都单调增加；某次暂定增购可以在交付前撤回到 g。

调整表前6小时应等于 g；后续没改的段填沿用的有效量，不能填0。最终表从逐段执行账本取 a，不能直接把18时的144维数组覆盖全天，否则可能丢失6/12时已执行修订。

日期从 2025-02-01 到12-31，334天，48,096个提交期段。一月完整执行日志有4,464段，全年度52,560段；不得用一月训练完后免费重置二月SOC。

应急合并只在同日相邻正e段进行；零段断开、跨日断开；费用仍逐段使用各自电价。存储原数值全精度，显示 `0.00`，先累计再显示。不得将 `5000 kW` 当某个十分钟段能量。

## 3. 四指定日论文表

## 4. 唯一 run 的文件清单

每次运行创建 `outputs/q3/<run_id>/`，严禁覆盖非空目录。至少包含：

`result3.xlsx`、`tables_q3.md`、`summary.json`、`run_metadata.json`、`run_status.json`、`ledger_full_year.csv`、`ledger_submission.csv`、`daily_summary.csv`、`emergency_events.csv`、`solver_log.csv`、`template_mapping.csv`、`contract_snapshots/`、`policy_snapshots/`、`forecast_archive/`、`scenario_manifest/`、`figures/`。

账本额外字段：`g0_kwh`、`effective_contract_kwh`、`increase_vs_g0_kwh`、`decrease_vs_g0_kwh`、`planned_cost_yuan`、`adjustment_cost_yuan`、`emergency_cost_yuan`、`total_cost_yuan`、`contract_version`、`latest_available_forecast_version`、`policy_forecast_version`、`update_action`。其余逐段物理量、误差、规则原始值、投影量延用 Q2。

快照记录每次允许发布时刻：读取预报ID和目标时间、修改前/后剩余合同、g0哈希、初始S、源日ID、候选/保留评分、求解可行性/gap/时限、最终 accept/keep/fallback 原因。历史快照不可原地更新。

summary 同时报告一月、提交期、全年三段，含费用拆分、增减电量、应急量/费/次数、未利用量、初末S、每日最差费用、求解次数及各阶段状态、guard接受/拒绝、回退、投影量。求解gap按0/6/12/18分组，不把大量日内0gap混入来美化日前gap。
