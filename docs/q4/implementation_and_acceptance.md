## 2. 从 Q3 复用前必须补的安全检查

这不是要求重做第三问，而是第四问复用组件的前置条件：

1. `q3_model.tail_value()` 目前仅检查有没有 x 和有限 fun，未完整验证 x、状态、线性约束和 SOC；故障注入中全零非法尾部仍返回0费用。新尾部求解必须检查所有有限数、状态、原始矩阵、变量界、SOC和互斥；失败返回无有效评分。
2. `score_candidate()` 当前会把带非零 tail_mode_violations 的值计入评分；`solve_q3_stage()` 的尾部模式计数也没有自动阻止成功。Q4 必须实现“违规→整数尾部重试→仍不合格则拒绝候选”。检查不能只写日志。
3. 尾部限时可行值只算一个已验证的可行续接成本，不称精确 Φ。guard 两候选估值精度严重不对称时保留旧策略；若使用上下界作严格保护，只有新方案上界低于旧方案下界才可声称严格改进。
4. 区分原始规划候选容差与实际执行容差。Q3 采用候选1e-4、执行/模式1e-6；Q4 可明确沿用此双层数值口径，但必须记录每类残差并用投影后的成本评分，不写“全部原始MILP残差≤1e-6”。单位不同的残差分别报告。
5. 记录真实求解器选项和线程数，不把“scipy没有显式线程参数”当作已锁定单线程的证据；未验证就标未知。不得靠删除失败日或挑选指定日更好的旧解修饰正式结果。

## 3. 时序算法

```text
按1/1到12/31逐日：
    接续上一天实际S
    创建0时受限信息视图，形成负载/PV/价格预测
    从已成熟历史构造固定源日联合情景
    求解本日g0与规则，校验并冻结；失败则用预登记因果回退
    对144个时段：
        若Q4-3且到6/12/18：
            只读取已完成前缀与已发布预报
            同源日更新PV情景，求剩余合同与规则
            在同一联合情景中比较新旧方案；可靠改善才采用
        固定本段有效合同a
        揭示当前L、PV、p，计算三维特征
        物理投影、更新S，用实际p逐段结算
        保存该段最终版本与不可改写账本
    当日本身完成后才追加其成熟残差
    保存可恢复状态，不在二月重置
```

日前无可行候选：g=max(当时点预测净负载,0)、x=0。日内失败：保留上一次合法有效合同和规则。所有回退必须不读未来。可加入更好的因果可行启发式，但须先通过预检且整组实验一致。

## 5. P1：短期预检及计算预算

先从1/1顺序跑至少20天，每条分支都预检；另验证2/1、四指定日和12/31的索引/快照恢复。跨日期测试可用明确初态的人工例，但不得冒充正式年轨迹。

同问题配对比较合理的限时（例如日前30/60秒，日内15/10/5秒起步），选定本机预算后锁定配置；这些是候选预算，不是无需验证的全年参数。先单进程运行，勿让多个年度作业争抢核心。求解器支持MIP起点时可加载因果可行启发式；不支持时仍保留外部回退，不假称已热启动。

预检必须报告：维度、变量/约束数、整数变量数、实际线程配置、时间分布、日前及各阶段gap分布、无可行解次数、尾部拒绝、guard接受/保留、投影次数/量、执行最大残差。3维8情景过慢时，先检查尺度、界和模型组装；可把2维价格情景版作为预登记简化备选，只用一月预检决定，解释为何删价格反馈，不能全年跑完后悄悄挑赢家。

没有必要承诺零回退；必须有合法回退并披露。修复影响真实决策时新建run，从最早受影响日期的可信状态连同历史档案继续重跑，不能仅替换某个指定日而保持后续旧SOC。

## 6. 最值得跑的实验

先通过两条主结果，再按优先级串行跑实验，所有费用使用同一附件4真实价：

1. **固定价策略对照**：复用Q2 A、Q3 F2的固定价决策机制，在相同初始条件下执行并按附件4结算，明确叫“固定价策略在波动价环境下的对照”。其策略不响应实际价时，固定快照重放可与仅换价收费等价，但绝不是Q4主优化结果。
2. **预测价重优化**：Q4-2/Q4-3主方案。与上一项比较，回答适应价格的价值；不能直接拿固定价下Q3的14,899,992.97元减Q4费用当作算法收益。
3. **价格情景与反馈消融**：同样的负载/PV情景与预算，比较价格仅点预测、联合价格情景但无价格反馈、联合价格情景+价格反馈。保留一致的信息和更新时钟。
4. **Q4-3改约价值**：同样光伏信息与0/6/12/18时钟，Q4-3允许改约对比冻结合同；进一步同g0、同S、同历史分叉，离线未来只用于评价，不进入候选采纳。
5. **价格可知性解释敏感性**：当天完整实际价在0时已知，独立重优化，不给未来负载/PV，不给次日实际价；至少一月配对检验，主结果完成后优先扩全年。名称为“当日价格已知参考”，不称已证明下界。
6. **Q4-2附件3权限与退款**：按README的两个解释开关独立短期重优化，报窗口、期初末库存与费用；短期0.7%之类差异不足以证明全年不敏感。

端到端全年策略各自从1月运行，二月初SOC自然可能不同：同时报告期初、期末，不能称每日状态都相同。用统一历史估值ν补充 Jcash+ν(Sstart−Send)时注明不是实付账单。必要时另做相同二月初值的受控实验。

所有预测指标写明样本范围与聚合方法：合并所有样本后开根的RMSE，与每日RMSE再平均不相同。时间分叉的剩余区间相互重叠，收益不能相加。接受计数区分1月、提交期、全年；回退不算普通keep，不能漏掉失败时刻。

## 8. 正式交付与验收

每条正式run保存：

`result4-2.xlsx`或`result4-3.xlsx`、四指定日表、`summary.json`、`run_metadata.json`、`run_status.json`、全年与提交期逐段账本、每日汇总、事件表、求解日志、合同/规则快照、预测及情景档案、模板映射、绘图数据和图片。

账本另含实际价、预测价、价格预测版本、p_scale、价格情景版本、策略版本、原g0/有效a/增减、三项实际费用；尾部估值单独记录。所有产物由同一run和同一账本生成，源码/配置/原始输入有SHA。正式运行树干净，禁止生成一半修改源代码后继续把结果绑定旧SHA。

Git只提交源码、配置、测试、文档和较小报告。完整运行归档为tar.gz/zip，提供每文件及压缩包SHA-256、真实可访问位置；仅给MANIFEST不算数据交付。每条正式结果对应独立run，不混其他重复运行的“更好一天”。

最终回复分开写：数学/代码变化、执行可行性、实际收益、求解最优性缺口、回退与其他限制、交付位置、Git推送是否成功。自检通过不冒称Astra独立验收通过。
